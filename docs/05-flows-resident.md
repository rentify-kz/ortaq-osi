# 05. Flows: жилец

**Платформа:** мобильное приложение (основное), веб (полный паритет функций).

Жилец — самая многочисленная и наименее мотивированная роль. Он не обязан пользоваться приложением: у него есть общий чат в WhatsApp, который работает. Поэтому каждый экран должен отвечать на вопрос «зачем я это открыл» за одну секунду, а любое действие, требующее больше трёх шагов, не будет выполнено.

---

## 5.1 Главный экран

Требование из исходного файла: *«Главная страница с актуальными вопросами — что сейчас решается, какой прогресс. Плюс summary на основе ИИ еженедельно. И в приоритете показывается что требует действия жильца (голосование)».*

Отсюда порядок блоков — сверху то, что требует действия, ниже то, что информирует.

```
│ ЖК Асыл Арман, блок 3      кв. 45  │
├─────────────────────────────────────┤
│ ⚠ ТРЕБУЕТ ВАШЕГО УЧАСТИЯ           │
│ ┌─────────────────────────────────┐ │
│ │ Голосование: замена лифта       │ │
│ │ Осталось 3 дня · 42% проголосо- │ │
│ │ вали                            │ │
│ │            [Проголосовать]      │ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ Взнос за сентябрь — 8 500 ₸     │ │
│ │ Срок до 25 сентября             │ │
│ │            [Оплатить]           │ │
│ └─────────────────────────────────┘ │
├─────────────────────────────────────┤
│ СЕЙЧАС РЕШАЕТСЯ                     │
│ Течь в подвале, 2 подъезд           │
│ ●───●───○───○  Закуп материалов     │
│                                     │
│ Ремонт козырька, 1 подъезд          │
│ ●───●───●───○  Выполняется          │
├─────────────────────────────────────┤
│ ЗА НЕДЕЛЮ                           │
│ Отремонтирован лифт во 2 подъезде,  │
│ заменены 4 лампы в подъездах,       │
│ проведена дезинсекция подвала.      │
│ Собрано 87% взносов.                │
├─────────────────────────────────────┤
│ ОБЪЯВЛЕНИЯ                          │
│ 📌 Отключение воды 12 сентября      │
└─────────────────────────────────────┘
```

**Логика блока «Требует вашего участия»:** активные голосования, где жилец ещё не проголосовал → неоплаченные начисления с приближающимся сроком → заявки жильца, где нужен его ответ. Если блок пуст — он скрывается целиком, а не показывает «ничего не требуется».

**Прогресс заявок** берётся из завершённых `RequestStage` — это то самое «у жильцов видно было прогресс заявки» из требований председателя. Жилец видит не статус «в работе», а конкретный этап.

**Сводка за неделю** генерируется ИИ каждый понедельник (см. [11-ai-layer.md](11-ai-layer.md#37-еженедельная-сводка)). Это ответ на главную претензию жильцов — «непонятно, что вообще делает ОСИ».

Эндпоинт: `GET /houses/:id/home`

## 5.2 Создание заявки

Требование: *«Открыть заявку с конкретным выбором места/этажа (двор, наружная/внутренняя часть дома)»*.

### Шаги

1. Кнопка «Создать заявку» на главном экране
2. **Выбор места** — визуальный, а не выпадающий список:

```
Где проблема?

┌──────────┐ ┌──────────┐ ┌──────────┐
│   🏢     │ │   🌳     │ │   🚗     │
│ В подъезде│ │ Во дворе │ │ Паркинг  │
└──────────┘ └──────────┘ └──────────┘
┌──────────┐ ┌──────────┐ ┌──────────┐
│   🏠     │ │   🧱     │ │   🔽     │
│В квартире│ │  Фасад   │ │  Подвал  │
└──────────┘ └──────────┘ └──────────┘
```

3. **Уточнение локации** — зависит от выбора:
   - Подъезд → номер подъезда + этаж
   - Двор → зона (детская площадка, парковка, газон, мусорные баки)
   - Квартира → подставляется квартира жильца
   - Фасад / кровля → подъезд + сторона дома
4. **Категория** — сантехника, электрика, отопление, лифт, уборка, мусор, безопасность, прочее
5. **Описание** — свободный текст
6. **Фото** — до 5 штук, необязательно, но система подсказывает: «Фото ускоряет решение»
7. Отправка

### Что происходит после отправки

Заявка уходит в `TRIAGE`, и жилец сразу видит: «Заявка №47 принята, проверяется». Фоновая задача проверяет её на дубликаты и осмысленность ([11-ai-layer.md](11-ai-layer.md#31-триаж-и-проверка-заявки)).

| Исход | Что видит жилец |
|---|---|
| Принята | «Заявка принята» + попадает в список председателя |
| Похожа на существующую | «Похоже, об этом уже сообщили» + ссылка на заявку №44 с предложением подписаться на неё |
| ИИ не понял | Заявка **всё равно уходит председателю** с пометкой «требует уточнения» |

**Важное решение: ИИ не отклоняет заявки сам.** Исходное требование звучало как «если неправильна, то отклоняет её». Мы реализуем это как рекомендацию председателю, а не автоматическое отклонение. Причина практическая: пожилой жилец, написавший «течёт сверху помогите», сформулировал плохо, но проблема у него настоящая. Автоотклонение таких заявок означает, что человек перестанет пользоваться приложением после первого раза — и вернётся в общий чат. Отклонение оставлено председателю, ИИ только помечает подозрительные.

Единственное исключение — **точный дубликат**, поданный тем же жильцом повторно в течение часа: он объединяется автоматически.

Эндпоинт: `POST /houses/:id/requests`

## 5.3 Отслеживание заявки

```
Заявка №47                          В работе
Течь в подвале, 2 подъезд

●───────●───────○───────○
Осмотр  Закуп   Ремонт  Проверка
 ✓       ✓      сейчас

Исполнитель: Сергей П., сантехник

── История ──
11 сен  Заявка принята
11 сен  Приоритет: высокий
12 сен  Назначен Сергей П.
12 сен  Этап «Осмотр» выполнен
        📷 2 фото
13 сен  Этап «Закуп материалов» выполнен
```

Фотографии работника появляются здесь **только после подтверждения председателем** — прямое требование «фото сразу отображается у жителей после подтверждения выполнения председателем».

Жилец может добавить комментарий или фото к своей заявке, пока она не закрыта. После закрытия — оценить решение (это даёт председателю обратную связь по работникам).

Эндпоинты: `GET /requests/:id`, `GET /requests/:id/activity`

## 5.4 Участие в голосовании

Требование: *«Участвовать в голосовании через eGov Mobile»*. Полная механика — в [09-voting-legal.md](09-voting-legal.md).

### Шаги

1. Уведомление о старте голосования (push + карточка на главной)
2. **Экран голосования:**

```
Замена лифта во 2 подъезде

До окончания: 3 дня 4 часа
Проголосовало: 42% (нужно 50%)

── Материалы ──
📎 Коммерческие предложения (3)
📎 Дефектный акт

── Вопрос 1 ──
Утвердить замену лифта во 2 подъезде
за счёт средств капитального ремонта?

  ○ За
  ○ Против
  ○ Воздержался

⚖ Требуется 2/3 голосов
   (крупный расход)
```

3. Жилец выбирает ответы
4. Нажимает «Подписать и отправить»
5. **Подписание через eGov mobile:**
   - Мобильное приложение → deeplink открывает eGov mobile
   - Веб → QR-код для сканирования из eGov mobile
6. Жилец подписывает бюллетень своей ЭЦП
7. Возврат в приложение → «Готово»
8. Сервер забирает подпись, проверяет и фиксирует бюллетень

```
✓ Ваш голос учтён
  12 сентября, 14:32
  Вес голоса: 0.78% (по площади 62,4 м²)
  Подписано ЭЦП
```

**Почему показывается вес голоса.** Это неочевидно для жильца — он ожидает «один человек, один голос». Явное указание «ваш голос весит 0.78% по площади вашей квартиры» снимает будущие споры о результатах и заодно объясняет требование закона.

### Ограничения

- Голосовать может **только верифицированный собственник**. Наниматель видит голосование, но кнопка недоступна с пояснением: «Голосовать может собственник помещения»
- Один бюллетень на помещение. При долевой собственности голосует назначенный представитель
- Изменить поданный голос нельзя — бюллетень подписан ЭЦП и юридически значим
- Промежуточные результаты скрыты до закрытия (только явка и кворум)

### Напоминания

Автоматические уведомления: за 3 дня, за 1 день, за 4 часа до окончания — только тем, кто ещё не проголосовал. Требование «напоминание (уведомление) для жильцов».

Эндпоинты: `POST /votes/:id/ballot/start`, `POST /votes/:id/ballot/complete`

## 5.5 Финансы дома

Требование: *«Дэшборд финансов — бюджет дома; разбивка куда направляются деньги (с возможностью просмотреть чек платежа)... Также в том же дашборде процент сборов»*.

Это центральный экран для доверия к ОСИ. Ключевое решение: **жилец видит те же цифры, из которых собирается официальный отчёт** — не пересказ председателя, а исходные данные.

```
Бюджет дома                    Сентябрь 2026 ▾

┌─────────────────────────────────────┐
│ Остаток на счетах                   │
│ Текущий счёт        1 840 000 ₸    │
│ Капремонт (сбер.)   4 200 000 ₸    │
└─────────────────────────────────────┘

Собрано за месяц       2 100 000 ₸
Потрачено              1 730 000 ₸

Собираемость               87.4%
████████████████████░░░

── КУДА УШЛИ ДЕНЬГИ ──

Услуги подрядчиков        640 000 ₸  37%
├ Обслуживание лифтов     180 000 ₸
├ Уборка МОП              220 000 ₸
├ Дезинсекция              40 000 ₸
└ Техобслуживание сетей   200 000 ₸

Оплата труда              480 000 ₸  28%
├ Управление объектом     280 000 ₸
└ Бухгалтерский учёт      200 000 ₸

Текущий ремонт            310 000 ₸  18%
Коммунальные услуги       180 000 ₸  10%
Налоги и отчисления        85 000 ₸   5%
Банковские услуги          35 000 ₸   2%
```

Нажатие на любую строку раскрывает отдельные операции:

```
Уборка МОП                       220 000 ₸

15 сен  ТОО «Таза Сервис»     110 000 ₸
        Уборка мест общего пользования
        📎 Чек   📎 Акт выполненных работ

01 сен  ТОО «Таза Сервис»     110 000 ₸
        📎 Чек   📎 Акт
```

Нажатие на «Чек» открывает **фотографию чека** — это и есть «с возможностью просмотреть чек платежа».

Названия категорий — формулировки из официальной формы отчёта, сокращённые для читаемости. Жилец, открывший потом официальный отчёт, увидит те же строки и те же суммы. Это делает проверку возможной, а не декларативной.

Эндпоинт: `GET /houses/:id/finance/overview`

### Что жилец НЕ видит

**Поимённый список должников.** Видна общая собираемость (87.4%), но не то, что квартира 45 не платит третий месяц.

Обоснование в [14-compliance-privacy.md](14-compliance-privacy.md#4-приватность-внутри-дома): это персональные данные, и их публикация на весь дом создаёт конфликты между соседями. Председатель и бухгалтер список видят — работа с должниками их обязанность.

## 5.6 Мои платежи

Требование: *«Платежи для жильца (за ОСИ, паркинг и т.п.) с ссылкой на платеж Kaspi. Возможность добавить чек дабы показать, что вы оплатили»*.

```
Мои платежи                        кв. 45

── К ОПЛАТЕ ──
┌─────────────────────────────────────┐
│ Взнос на содержание · сентябрь      │
│ 8 500 ₸          до 25 сентября     │
│                                     │
│ [Оплатить через Kaspi] [Загрузить  │
│                          чек]       │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ Паркинг · сентябрь                  │
│ 12 000 ₸         до 25 сентября     │
└─────────────────────────────────────┘

── ИСТОРИЯ ──
Август    Взнос 8 500 ₸    ✓ Оплачено
Август    Паркинг 12 000 ₸ ✓ Оплачено
Июль      Взнос 8 500 ₸    ✓ Оплачено
```

### Оплата

1. «Оплатить через Kaspi» → открывается приложение Kaspi с заполненными реквизитами и суммой
2. Жилец платит в Kaspi
3. Возвращается в приложение → «Загрузить чек»
4. Фотографирует или выбирает скриншот чека
5. Чек уходит на распознавание

### Что происходит с чеком

Фоновая задача извлекает сумму, дату, получателя и номер транзакции ([11-ai-layer.md](11-ai-layer.md#32-распознавание-чека)) и сверяет с начислением:

| Результат | Статус | Что видит жилец |
|---|---|---|
| Всё сошлось | `PENDING_REVIEW` | «Чек принят, ожидает подтверждения» |
| Сумма меньше начисления | `PENDING_REVIEW` + флаг | «Чек принят. Сумма меньше начисленной» |
| Чек уже загружался | `FLAGGED` | «Этот чек уже был загружен ранее» |
| Не распознан | `PENDING_REVIEW` + флаг | «Чек принят, проверит председатель» |

**Подтверждает всегда председатель или бухгалтер.** Автоматического зачёта нет: чек — это фотография, которую можно переиспользовать или подделать, и решение о зачёте денег остаётся за человеком.

**Привязка к квартире** происходит автоматически через `UnitOwnership` — это то самое «сразу привязывается к номеру, а номер указан по квартирам, и поэтому у ОСИ видно будет кто оплатил, а кто нет».

Эндпоинты: `GET /me/charges`, `GET /charges/:id/payment-link`, `POST /charges/:id/payment`

## 5.7 Объявления

```
Объявления

📌 Отключение горячей воды
   12–14 сентября, плановые работы
   вчера

   Уважаемые жильцы! С 12 по 14 сентября
   будет отключена горячая вода в связи
   с плановой опрессовкой системы.

   Подъезды 1–4 · от председателя

── Ранее ──
   Субботник во дворе          5 сентября
   Новый график консьержей     1 сентября
```

Жилец видит только адресованные ему объявления: общие для всех, для его подъезда или лично ему. Объявления для персонала он не видит.

Закреплённые (`is_pinned`) — сверху. Прочтение отмечается автоматически и даёт председателю статистику охвата.

Эндпоинт: `GET /houses/:id/announcements`

## 5.8 Дом: персонал и документы

Требование прозрачности — жильцы должны знать, кто работает в их доме.

```
Мой дом

── ПРАВЛЕНИЕ ──
Иванов И.И.          Председатель ОСИ
                     +7 707 ••• •• 11

── ПЕРСОНАЛ ──
Сергей П.            Сантехник
                     пн–пт 9:00–18:00
Айгуль К.            Уборщица, подъезды 1–2
Нурлан Б.            Дворник

── ПОДРЯДЧИКИ ──
ТОО «Таза Сервис»    Уборка МОП
                     договор до 31.12.2026
ТОО «Лифт-Сервис»    Обслуживание лифтов

── ДОКУМЕНТЫ ──
📄 Отчёт за август 2026
📄 Протокол №4 — замена лифта
📄 Отчёт за июль 2026
```

Отчёты и протоколы доступны всем жильцам после публикации — это требование закона о размещении отчёта в общедоступном месте, выполненное цифровым способом.

Эндпоинты: `GET /houses/:id/staff`, `GET /houses/:id/contractors`, `GET /houses/:id/reports`

## 5.9 Уведомления

| Событие | Канал | Почему так |
|---|---|---|
| Старт голосования | Push + карточка | Требует действия |
| Напоминание о голосовании | Push | За 3 дня, 1 день, 4 часа |
| Смена этапа своей заявки | Push | Ожидаемая обратная связь |
| Заявка выполнена | Push + фото | Главный момент доверия |
| Новое объявление | Push | Кроме адресных чужим |
| Приближается срок оплаты | Push | За 5 дней и в день срока |
| Платёж подтверждён | Push | Закрывает неопределённость |
| Еженедельная сводка | In-app | Не push: не срочно, а push каждую неделю раздражает |
| Опубликован отчёт | Push | Раз в месяц, важен для доверия |

Настройки уведомлений — по категориям. Отключить можно всё, кроме голосований: это юридически значимое уведомление, которое ОСИ обязана направить, и его отключение создало бы основание оспорить результаты.

## 5.10 Что жилец не может

Границы роли, зафиксированные явно:

| Действие | Почему нет |
|---|---|
| Видеть заявки соседей про их квартиры | Личные данные. Заявки по общему имуществу видны всем |
| Видеть поимённых должников | Персональные данные, конфликты |
| Видеть контакты других жильцов | Не нужно для функций приложения |
| Менять свою заявку после принятия в работу | Иначе исполнитель делает не то, что согласовано. Можно комментировать |
| Голосовать без верификации | Требование ст. 44 об обязательной идентификации |
| Голосовать, будучи нанимателем | Голос принадлежит собственности |
| Отозвать поданный бюллетень | Подписан ЭЦП, юридически значим |
