# 00. Обзор продукта

## Проблема

Управление многоквартирным домом в Казахстане после реформы ОСИ держится на одном человеке — председателе. У него на руках заявки жильцов в WhatsApp, чеки в кармане, договоры с подрядчиками в папке, обязательная отчётность до 20 числа и собрания, которые почти невозможно собрать физически.

У жильцов зеркальная проблема: они платят взносы каждый месяц и не понимают, куда уходят деньги. Заявка, отправленная в общий чат, растворяется. Собрание, на котором принимаются решения о их деньгах, проходит без них.

Обе стороны страдают от одного и того же — **отсутствия общего, достоверного и доступного состояния дома**.

## Что делает платформа

Платформа переводит это состояние в единую систему, где каждое действие оставляет след:

- Заявка жильца становится задачей с этапами, исполнителем и фотоотчётом — прогресс виден всем
- Каждая трата привязана к чеку и к строке официальной формы отчёта — отчёт собирается сам
- Голосование проходит с юридически значимой подписью через eGov, протокол формируется автоматически
- Юридическая рутина — протоколы, отчёты, ссылки на статьи закона — снимается с председателя

## Цели по ролям

**Для жильцов:**
1. Прозрачность — видно, сколько собрано, сколько потрачено и на что, с подтверждающим чеком
2. Удобство голосования — из телефона, без физического собрания
3. Быстрое решение вопросов — заявка с понятным статусом вместо сообщения в чате
4. Понимание — еженедельная сводка о том, что происходит в доме

**Для ОСИ:**
1. Ясность — все заявки, задачи, финансы и документы в одном месте
2. Автоматизация — отчёты, протоколы и распределение задач формируются системой
3. Скорость — приоритизация заявок и передача исполнителю в два действия
4. Юридическое упрощение — помощник по законодательству и готовые документы по форме

## Роли

| Роль | Кто это | Как попадает в систему | Основные задачи |
|---|---|---|---|
| `PLATFORM_ADMIN` | Сотрудник платформы | Заводится вручную при развёртывании | Создаёт организации и дома, выдаёт доступ председателям |
| `CHAIRMAN` | Председатель ОСИ | Учётку создаёт админ платформы, вход по почте | Управляет домом: заявки, задачи, финансы, голосования, отчёты |
| `ACCOUNTANT` | Бухгалтер ОСИ | Приглашается председателем по почте | Ведёт финансы, подписывает отчёт |
| `WORKER` | Сантехник, электрик, дворник, консьерж | Добавляется председателем, вход по телефону | Выполняет задачи, отмечает выполнение с фото |
| `RESIDENT` | Собственник или наниматель | Регистрируется по ссылке-приглашению или заявке | Создаёт заявки, голосует, оплачивает, следит за бюджетом |
| `CONTRACTOR` | Подрядная организация | Запись в справочнике (вход — после MVP) | Выполняет работы по договору |

Роли `CHAIRMAN` и `ACCOUNTANT` различаются правами на деньги: председатель утверждает, бухгалтер вносит. Обе подписывают ежемесячный отчёт — это требование официальной формы, а не наше решение.

Роль `ACCOUNTANT` опциональна: в маленьких ОСИ председатель совмещает обе, и система это допускает.

Роль в доме (`HouseMembership.role`) — служебная. Права жильца — заявки, свои начисления, голос — выводятся из связи с помещением (`UnitOwnership`), а не из роли `RESIDENT`. Поэтому председатель, живущий в своём доме, голосует и платит как собственник, не имея второй роли.

## Глоссарий

| Термин | Значение |
|---|---|
| **ОСИ** | Объединение собственников имущества — юрлицо, управляющее домом. Пришло на смену КСК |
| **ПТ** | Простое товарищество — альтернативная форма управления домом без образования юрлица |
| **Объект кондоминиума** | Юридическое название дома как объекта совместной собственности. В интерфейсе — «дом» или «ЖК» |
| **Общее имущество** | Подъезды, крыша, подвал, лифты, двор, инженерные сети — всё, что принадлежит собственникам совместно |
| **Помещение (`Unit`)** | Квартира, нежилое помещение или паркоместо. Единица собственности и **единица голоса** |
| **Кворум** | Минимальная доля собственников, при которой собрание правомочно. Более 50%, считается по площади |
| **Целевой взнос** | Разовый взнос на что-то, не предусмотренное сметой. Требует решения собрания |
| **Капитальный ремонт** | Накопления на отдельном сберегательном счёте. Тратятся только по решению собрания |
| **Дефектный акт** | Документ, фиксирующий необходимость ремонта. Основание для расходов по текущему ремонту |
| **Акт выполненных работ** | Подтверждение, что работа принята. Прикладывается к отчёту |
| **ЭЦП** | Электронная цифровая подпись. Здесь — подписание в eGov mobile по QR через Smart Bridge |
| **ИИН** | Индивидуальный идентификационный номер. Извлекается из сертификата ЭЦП |
| **Smart Bridge** | Государственная интеграционная платформа. Через неё система подписывает документы в eGov mobile и запрашивает сведения о недвижимости |
| **Digital ID** | Подтверждение личности через eGov. Возвращает подтверждённые государством ИИН и ФИО |
| **ГБД РН** | Государственная база данных «Регистр недвижимости». Источник сведений о праве собственности на помещение |

## Границы MVP

### Входит

- Админ-панель: организации, дома, помещения, учётки председателей
- Онбординг жильцов по ссылке и через ручное подтверждение, верификация личности через Digital ID и права собственности через ГБД РН
- Заявки с выбором места, приоритетом, этапами и фотофиксацией
- Задачи для работников, включая повторяющиеся по расписанию
- Объявления с адресацией (всем / персоналу / конкретным людям)
- Бюджет дома по официальному плану счетов, чеки, дашборд для жильцов
- Начисления жильцам, оплата по ссылке Kaspi, подтверждение чеком, выявление должников
- Голосования с юридическими порогами, ЭЦП-бюллетени, автоматический протокол
- Договоры с подрядчиками с подписанием ЭЦП обеих сторон
- Ежемесячный отчёт по официальной форме
- ИИ: триаж заявок, распознавание чеков, голосовые задачи, сравнение КП, юрпомощник, еженедельные сводки

### Не входит (осознанно отложено)

| Отложено | Почему |
|---|---|
| Kaspi Pay merchant API | Требует договора ОСИ с банком. Архитектура готова, включается без переписывания |
| Личные кабинеты подрядчиков | Сначала нужно проверить, что подрядчики вообще готовы пользоваться системой |
| Приборы учёта и показания счётчиков | Отдельный большой домен, не входит в исходные требования |
| Чат между жильцами | Дублирует WhatsApp, требует модерации, порождает конфликты |
| Казахский язык интерфейса | Обязателен к релизу, но не блокирует проектирование. Все строки выносятся в i18n с первого дня |
| Интеграция с 1С / бухгалтерией | После подтверждения спроса |
| Общие собрания в очной форме | MVP покрывает электронное голосование (ст. 44) и письменный опрос (ст. 43) |

## Принципы, на которых построена система

**1. Прозрачность подтверждается данными, а не обещаниями.**
Каждая трата привязана к чеку, каждое действие — к записи в неизменяемом журнале аудита. Жилец видит не сводку, составленную председателем, а те же самые цифры, из которых собирается официальный отчёт.

**2. ИИ готовит, человек решает.**
Модель делает черновик, предлагает, распознаёт и суммирует. Отклонение заявки, утверждение расхода, подписание протокола — всегда действие человека. Это не только про безопасность: ответственность за решение по закону лежит на председателе, и система не должна создавать иллюзию, что её можно переложить.

**3. Закон — это часть модели данных, а не текст в справке.**
Пороги голосования, кворум по площади, сроки уведомления, строки отчётной формы — всё это зашито в структуры и проверки. Систему нельзя случайно использовать так, чтобы получился ничтожный протокол.

**4. Дом изолирован от дома.**
Платформа обслуживает много ОСИ. Данные одного дома недоступны другому на уровне приложения, базы и тестов.

**5. Никаких персональных данных в ИИ.**
Обязательный слой обезличивания. Не настройка, а архитектурный инвариант.
