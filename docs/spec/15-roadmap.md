# 15. Роадмап

Порядок фаз определяется зависимостями, а не привлекательностью функций. Голосование выглядит самой интересной частью продукта, но оно требует верифицированных собственников и заполненных площадей — поэтому идёт четвёртым.

---

## Фаза 0 — Админ-панель и провижининг

**Зачем первой:** без неё в систему физически некого пустить. Председатель не регистрируется сам, жилец не может войти в дом, которого нет.

| Блок | Состав |
|---|---|
| Админ-панель | Организации, дома, связывание, генерация помещений, состояние готовности |
| Учётки председателей | Заведение по почте, письмо-приглашение, установка пароля, обязательная 2FA |
| Приглашения | Ссылки для чата, персональные приглашения, отзыв и перевыпуск |
| Заявки на вступление | Очередь, подтверждение председателем |
| Основа безопасности | Изоляция домов (скоуп + RLS + тесты), сессии, журнал аудита с хеш-цепочкой, секреты в Lockbox |
| Интерфейсы интеграций | `SignatureProvider`, `IdentityProvider`, `PropertyRegistryProvider` с mock-реализациями |

**Результат:** можно завести реальную ОСИ, дать доступ председателю и пригласить жильцов.

Фаза намеренно отделена от следующей: это внутренний инструмент на 3–4 экрана, его можно собрать быстро и начать заводить реальные дома, пока идёт работа над остальным.

**Параллельно с фазой 0 — подача заявки на регистрацию информационной системы в Smart Bridge.** Срок согласования не зависит от команды, поэтому он запускается первым. Разработка на него не опирается: до подключения все государственные сервисы — заглушки.

**Основа безопасности входит именно сюда** — переделать изоляцию домов позже означает переписать каждый эндпоинт.

---

## Фаза 1 — Фундамент

| Блок | Состав |
|---|---|
| Регистрация жильцов | Телефон + OTP, привязка к помещению |
| Верификация личности | Digital ID: подтверждённые ИИН и ФИО |
| Верификация собственности | ГБД РН через Smart Bridge; запасной путь — загруженный реестр; ручное подтверждение |
| Реестр собственников | Импорт XLSX/CSV, превью с ошибками, хеширование ИИН (запасной источник) |
| Бухгалтер | Добавление председателем, пароль + 2FA |
| Заполнение площадей | Массовый ввод, переход дома в `is_voting_ready` |
| Роли и права | RBAC по всем ролям, матрица доступа |
| Объявления | Создание, адресация, статистика прочтений |
| Персонал и подрядчики | Справочники, видимость жильцам |
| Уведомления | Push, SMS, каналы, тихие часы |
| Безопасность фазы | Защита OTP и приглашений, шифрование ИИН, согласия на обработку ПДн |

**Результат:** дом заселён верифицированными жильцами, работает базовая коммуникация.

Первая фаза с внешней интеграцией. Разрабатывается на заглушках; переключение на реальный Smart Bridge — после регистрации, с запасом времени на отладку в staging.

---

## Фаза 2 — Заявки и задачи

| Блок | Состав |
|---|---|
| Заявки | Создание с выбором места, категории, фото |
| Триаж | Проверка на дубликаты и осмысленность, предложение приоритета |
| Этапы | Создание, отметка выполнения, прогресс у жильцов |
| Задачи | Назначение, специализации, уведомления исполнителю |
| Выполнение | Фотофиксация, подтверждение председателем, показ жильцам |
| Повторяющиеся задачи | Шаблоны с RRULE, автопорождение |
| Мобильное для работника | Отдельный интерфейс, офлайн-режим |
| Главный экран жильца | Активные вопросы с прогрессом |

**Результат:** полный цикл «жилец сообщил о проблеме → работник устранил → жилец увидел фото результата». Это первая фаза, дающая жильцу ощутимую пользу.

## Фаза 3 — Финансы

| Блок | Состав |
|---|---|
| План счетов | Справочник из официальной формы (**Приказ №362**) |
| Счета и транзакции | Текущий и сберегательный, проведение, аннулирование |
| Распознавание чеков | OCR, предзаполнение формы расхода |
| Начисления | Тарифы, автогенерация 1 числа |
| Оплаты | Ссылка Kaspi, загрузка чека, подтверждение |
| Защита от подделки | Хеши чеков, уникальность номера транзакции |
| Дашборд | Для жильцов и председателя, просмотр чеков |
| Должники | Выявление, персональные напоминания |
| Отчётность | Автогенерация 15 числа, проверка полноты, подписание ЭЦП, публикация |
| Договоры | Договоры с подрядчиками, подписание ЭЦП обеих сторон, связь с расходами 6.2.1 |
| Безопасность фазы | Step-up на денежных операциях, идемпотентность |

**Результат:** закрыто обещание прозрачности для жильцов и снята обязательная отчётность с председателя.

Самая объёмная фаза. Отчётность зависит от плана счетов, поэтому внутри фазы порядок жёсткий: справочник → транзакции → отчёт.

## Фаза 4 — Голосования

| Блок | Состав |
|---|---|
| Создание голосования | Типы решений, автовывод порогов, вопросы, материалы |
| Сроки | Контроль пятидневного уведомления, напоминания |
| Снимок реестра | Заморозка весов при старте |
| Бюллетени | Подписание в eGov mobile через Smart Bridge, серверная проверка, сверка ИИН с Digital ID, append-only |
| Подсчёт | Кворум по площади, пороги, результаты |
| Протокол | Автогенерация, подписание председателем и секретарём, публикация |
| Письменный опрос | Ст. 43, бумажные бюллетени со сканами |

**Результат:** ОСИ может принимать юридически значимые решения без физического собрания.

Зависит от фазы 1 (верифицированные собственники) и от заполненных площадей. Технически могла бы идти раньше финансов, но крупные расходы — главный предмет голосований, поэтому финансовый контекст должен существовать.

## Фаза 5 — ИИ-надстройка

| Блок | Состав |
|---|---|
| Подсказки по заявкам | План действий, специализация |
| Голосовые задачи | Распознавание речи, извлечение задач, распределение |
| Сравнение КП | Разбор PDF, матрица, рекомендация, связка с голосованием |
| Юридический помощник | RAG по законодательству, цитаты статей |
| Еженедельные сводки | Автопубликация по понедельникам |
| Безопасность фазы | Защита от prompt injection, лимиты токенов, тесты обезличивания |

**Результат:** снята интеллектуальная рутина председателя.

Идёт последней намеренно: это надстройка над работающей системой. Базовый триаж заявок реализуется раньше, в фазе 2, — без него заявки тонут в дубликатах.

## Безопасность по фазам

Отдельной «фазы безопасности» нет намеренно — то, что откладывают, дороже всего переделывать.

| Фаза | Что входит |
|---|---|
| 0 | Изоляция домов (скоуп + RLS + тесты), сессии и ротация токенов, 2FA, аудит с хеш-цепочкой, секреты в Lockbox |
| 1 | Защита OTP, безопасность приглашений, шифрование ИИН, согласия |
| 2 | Права на файлы, вырезание EXIF, антивирус |
| 3 | Step-up на деньгах, идемпотентность, защита от повторной подачи чеков |
| 4 | Append-only бюллетени, снимок реестра, серверная проверка подписи |
| 5 | Защита от prompt injection, лимиты токенов, тесты обезличивания |

**Перед первым реальным домом в продакшене** — внешнее тестирование на проникновение с упором на междомовую изоляцию и целостность голосований, плюс учебное восстановление из бэкапа.

---

## Что проверять на каждой фазе

| Фаза | Контрольный вопрос |
|---|---|
| 0 | Может ли председатель дома A получить хоть что-то о доме B? |
| 1 | Может ли непроверенный человек по ссылке из чата получить право голоса? |
| 2 | Видит ли жилец фото результата, и только после подтверждения председателем? |
| 3 | Сходится ли дашборд жильца с официальным отчётом до копейки? |
| 4 | Даёт ли пересчёт голосования через месяц те же цифры, что в протоколе? |
| 5 | Работает ли система полностью при отключённом Gemini? |

Последний вопрос — регрессионный тест, а не разовая проверка: ИИ-функции не должны незаметно стать критичными.

## Риски

| Риск | Смягчение |
|---|---|
| **Регистрация в Smart Bridge затянется** | Разработка на заглушках, заявка подаётся в начале фазы 0. Если к пилоту доступа нет — пилот без голосований и с ручной верификацией собственности председателем |
| **Сервисы Smart Bridge не отдают нужных данных** (например, ГБД РН без номера помещения) | `PropertyRegistryProvider` за интерфейсом; запасной путь — загруженный реестр и ручное подтверждение. Проверить на тестовом контуре сразу после подключения |
| **Формы отчётности из Приказа №362 отличаются** от известной структуры | `ReportTemplate.schema` — данные, а не код. Получить актуальный текст до фазы 3 |
| **Пороги голосования трактуются иначе** | Юридическая проверка до фазы 4; пороги выводятся из `decision_type`, меняются в одном месте |
| **Жильцы не устанавливают приложение** | Веб с полным паритетом; онбординг по ссылке в один переход; ценность видна с первого экрана |
| **Председатели не переходят с WhatsApp** | Фаза 2 даёт им ощутимую выгоду (заявки не теряются), фаза 3 — снятие отчётности |
| **Бесплатного лимита Gemini не хватит** | Лимиты на дом, деградация без блокировки основной работы, `AiProvider` допускает смену модели |
| **Недобросовестный председатель** | Аудит с хеш-цепочкой, доступный жильцам; неизменяемость транзакций и бюллетеней; тайна голосования от председателя |

Последний риск — единственный, который нельзя устранить технически до конца. Система может сделать злоупотребление **видимым**, но не может его предотвратить, пока председатель распоряжается деньгами по закону. Ставка сделана на прозрачность и неизменяемость записей: то, что нельзя скрыть, обычно не делают.
