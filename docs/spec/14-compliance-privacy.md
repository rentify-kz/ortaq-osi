# 14. Персональные данные и соответствие законодательству

> **Дисклеймер.** Документ фиксирует понимание требований на момент проектирования (сентябрь 2026) и описывает технические решения. Он не является юридическим заключением. Перед запуском политика обработки данных и формы согласий должны быть проверены юристом.

---

## 1. Какие данные обрабатываются

| Категория | Состав | Основание |
|---|---|---|
| Идентификационные | ФИО, ИИН, номер телефона, email | Требование ст. 44 об идентификации собственника при электронном голосовании |
| Имущественные | Номер помещения, площадь, доля, вид собственности | Расчёт веса голоса и начислений |
| Финансовые | Начисления, оплаты, задолженность, чеки | Ведение учёта и отчётности ОСИ |
| Поведенческие | Заявки, голоса, прочтения объявлений | Работа сервиса |
| Технические | IP, устройство, сессии | Безопасность |

**Принцип минимизации соблюдается буквально:** сканы удостоверений личности не хранятся вообще. Из сертификата ЭЦП берутся только ИИН и ФИО — этого достаточно для идентификации, и это существенно меньше, чем «загрузите фото удостоверения», как делают многие сервисы.

Из чеков не извлекается ФИО плательщика: привязка идёт через `UnitOwnership`, а не через имя на чеке. Номер карты маскируется до последних четырёх цифр сразу при распознавании.

## 2. Локализация данных

**Закон РК №94-V:** персональные данные граждан Казахстана хранятся в базе, находящейся на территории РК.

| Данные | Где |
|---|---|
| БД (все персональные данные) | Yandex Cloud Managed PostgreSQL, регион **`kz1`** |
| Файлы (чеки, фото, документы) | Yandex Object Storage, **`kz1`** |
| Бэкапы | **`kz1`**, шифрованные, не покидают регион |
| Логи | **`kz1`**, без персональных данных |

### Трансграничная передача: её нет

Закон допускает передачу данных за границу при явном согласии субъекта и достаточной защите в стране получателя. Мы этим путём **не идём**.

Решение пользователя — «конфиденциальную часть изначально не давать в ИИ» — реализовано как полное обезличивание перед любым вызовом Gemini. Персональные данные за пределы Казахстана **не передаются вообще**, поэтому вопрос трансграничной передачи не возникает.

Это надёжнее альтернативы. Путь через согласия требовал бы: собирать отдельное согласие на передачу в США, обосновывать достаточность защиты, вести учёт отозванных согласий и исключать этих жильцов из ИИ-функций. Обезличивание снимает всё это на уровне архитектуры.

**Что уходит наружу:** обезличенный текст в Gemini (США) и запросы к государственным сервисам через Smart Bridge (Казахстан): документы на подписание, Digital ID, запрос в ГБД РН по ИИН с согласия субъекта.

**Сведения о недвижимости.** Запрос в ГБД РН выполняется только после явного согласия жильца, версия текста согласия сохраняется. Из ответа хранится только результат сопоставления с домом; остальная недвижимость жильца не сохраняется.

Техническая реализация обезличивания — [11-ai-layer.md](11-ai-layer.md#2-слой-обезличивания).

## 3. Шифрование ИИН

ИИН — наиболее чувствительный идентификатор в системе: он однозначно определяет гражданина и используется во множестве государственных и банковских систем.

Хранится в **двух формах**:

| Форма | Как | Зачем |
|---|---|---|
| `iin_encrypted` | AES-256-GCM, ключ в Yandex Lockbox | Показать владельцу, вписать в протокол |
| `iin_hash` | HMAC-SHA256 с отдельным ключом | Сверка с реестром и поиск **без расшифровки** |

В таблице `OwnerRegistryEntry` хранится **только хеш** — сам ИИН из загруженного реестра не сохраняется.

Практический смысл: при верификации жильца система хеширует ИИН, полученный из Digital ID, тем же ключом и сравнивает с загруженным реестром (запасной путь) и с ИИН из сертификата при каждой подписи. Расшифровка не требуется. Утечка таблицы реестра не раскрывает ИИН жильцов.

HMAC, а не обычный хеш, потому что ИИН — короткое значение из ограниченного пространства: простой SHA-256 перебирается за разумное время, HMAC с секретным ключом — нет.

## 4. Приватность внутри дома

Самое важное продуктовое решение этого документа.

### Правило

**Жильцы видят агрегированные финансы дома, но не долги соседей поимённо.** Список должников доступен только председателю и бухгалтеру.

### Обоснование

Исходное требование звучало так: *«сразу привязывается к номеру, а номер указан по квартирам и поэтому у ОСИ видно будет кто оплатил а кто нет»*. Оно выполнено полностью — ОСИ видит платежи по квартирам.

Но публикация такого списка **всему дому** не делается, и возможность такая в системе не предусмотрена. Три причины:

1. **Это персональные данные.** Финансовое положение конкретного человека, связанное с его именем и адресом. Публикация третьим лицам без его согласия — нарушение.

2. **Это порождает конфликты.** Публичный список должников в подъезде — известная практика, которая приводит к травле, порче имущества и переходу соседских отношений в открытую вражду. Платформа, создающая такой инструмент, несёт часть ответственности за последствия.

3. **Это не решает задачу.** Работа с должниками — обязанность председателя, у которого есть законные инструменты вплоть до суда. Публичный позор не увеличивает собираемость, а увеличивает конфликтность.

Жильцы видят агрегат — **процент собираемости**. Этого достаточно для контроля за работой ОСИ: если собираемость 60%, вопрос к председателю есть, и он может ответить, не называя фамилий.

### Матрица видимости

| Данные | Жилец | Работник | Бухгалтер | Председатель |
|---|---|---|---|---|
| Свои начисления и оплаты | да | да | да | да |
| Начисления соседей | **нет** | **нет** | да | да |
| Список должников поимённо | **нет** | **нет** | да | да |
| Процент собираемости | да | нет | да | да |
| Бюджет дома, расходы, чеки | да | нет | да | да |
| ФИО и контакты соседей | **нет** | **нет** | частично | да |
| Заявки соседей о своих квартирах | **нет** | только назначенные | нет | да |
| Заявки по общему имуществу | да | назначенные | нет | да |
| Персонал: ФИО, должность, рабочий телефон | да | да | да | да |
| Персонал: зарплата, личные данные | **нет** | **нет** | да | да |
| Протоколы и отчёты | да | нет | да | да |
| Кто как проголосовал | **нет** | **нет** | **нет** | **нет** |
| Журнал аудита | нет | нет | нет | да |

Последняя строка: **тайна голосования сохраняется даже от председателя.** Он видит, кто проголосовал (это нужно для кворума и фиксируется в протоколе), но не видит, как именно. Иначе голосование против позиции председателя становится небезопасным для жильца, а сама процедура — фиктивной.

Тайна обеспечивается ограничением доступа, а не криптографией: ЭЦП связывает подписанта с содержимым бюллетеня. Границы гарантии — [09-voting-legal.md](09-voting-legal.md#тайна-голосования-что-гарантируется-и-что-нет).

## 5. Согласия

| Согласие | Когда | Как |
|---|---|---|
| На обработку персональных данных | При регистрации | **Подписывается ЭЦП** — это и есть документ верификации |
| На получение уведомлений | При регистрации | Чекбокс, отзывается в настройках |
| С правилами сервиса | При регистрации | Чекбокс с версией документа |

Совмещение согласия на обработку ПДн с процедурой верификации — удачное следствие архитектуры: документ, который жилец подписывает своей ЭЦП для подтверждения личности, и есть согласие. Получается юридически значимое согласие с подтверждённой датой и подписью, а не галочка.

Версия текста согласия фиксируется. При изменении политики требуется новое согласие, старые сохраняются в истории.

**Уведомления о голосованиях отключить нельзя** — это юридически значимое извещение, которое ОСИ обязана направить собственнику. Возможность отключения создала бы основание оспорить результаты.

## 6. Права субъекта данных

| Право | Реализация |
|---|---|
| Знать, какие данные обрабатываются | Раздел «Мои данные» в профиле |
| Получить копию | Экспорт в машиночитаемом формате по запросу |
| Исправить неточные | Самостоятельно или через председателя для данных о собственности |
| Отозвать согласие | Через поддержку; ведёт к прекращению доступа к сервису |
| Удалить данные | С ограничениями — см. ниже |

### Ограничения на удаление

Не всё можно удалить по требованию, и это нужно объяснять честно:

| Данные | Удаляются | Почему |
|---|---|---|
| Профиль, контакты, аватар | да | Нет оснований хранить |
| Заявки, комментарии | обезличиваются | Нужны для истории дома |
| **Бюллетени** | **нет** | Юридически значимый документ, 5 лет |
| **Финансовые операции** | **нет** | Бухгалтерская отчётность |
| **Подписи ЭЦП** | **нет** | Доказательная база |
| **Журнал аудита** | **нет** | Append-only по построению |

Это соответствует общему принципу: право на удаление не абсолютно и уступает обязанностям по хранению отчётности и юридически значимых документов. Пользователю показывается прямое объяснение, что именно останется и почему.

## 8. Роли по закону о персональных данных

| Сторона | Роль | Что делает |
|---|---|---|
| **ОСИ** | Собственник данных | Определяет цели обработки, отвечает перед жильцами |
| **Платформа** | Оператор | Обрабатывает по поручению ОСИ |
| **Жилец** | Субъект | Даёт согласие, реализует права |

Разграничение существенно: платформа обрабатывает данные **по поручению ОСИ**, а не в своих интересах. Это должно быть закреплено договором между платформой и каждой ОСИ, с указанием целей, состава данных, мер защиты и порядка действий при инциденте.

Практическое следствие: платформа не может использовать данные жильцов для собственных целей — аналитики, маркетинга, обучения моделей. Это отдельно фиксируется в договоре и в политике.

## 9. Чек-лист перед запуском

Юридическая часть, которую нужно закрыть до первого реального дома:

- [ ] Политика обработки персональных данных, проверенная юристом
- [ ] Формы согласий с версионированием
- [ ] Договор между платформой и ОСИ с разграничением ролей оператора и собственника
- [ ] Уведомление уполномоченного органа об обработке ПДн, если требуется
- [ ] Назначенное ответственное лицо за защиту данных
- [ ] Процедура реагирования на утечку с установленными сроками уведомления
- [ ] Проверка порогов голосования и сроков уведомления практикующим юристом по жилищному праву
- [ ] **Актуальные формы отчётности из Приказа №362 от 12.09.2025** (Приказ №20247 отменён)
- [ ] Регистрация информационной системы в Smart Bridge и доступ к сервисам: QR-подписание, Digital ID, ГБД РН
- [ ] Текст согласия на запрос сведений из ГБД РН, проверенный юристом
- [ ] Внешнее тестирование на проникновение
- [ ] Учебное восстановление из бэкапа

Два пункта стоит выделить: формы отчётности взяты из отменённого приказа и **обязательно** требуют сверки с действующим; пороги голосования собраны из вторичных источников и требуют юридического подтверждения. Оба — в местах, где ошибка обнаружится поздно и дорого.
