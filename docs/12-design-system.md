# 12. Дизайн-система

Стиль — Rentify: белый фон, светло-зелёные поверхности, тёмно-зелёный акцент, чёрный текст, шрифт Inter. Много воздуха, мягкие скругления, минимум границ.

**Принцип реализации:** токены задаются один раз в `packages/design-tokens` и экспортируются и в Tailwind-конфиг, и в React Native StyleSheet. Без этого веб и мобильное приложение разъедутся в течение месяца.

### Правила применения

Зелёный — цвет **действия и подтверждения**, а не декорации. Если зелёным покрашено всё, акцентная кнопка перестаёт выделяться.

| Элемент | Цвет |
|---|---|
| Основная кнопка | фон `accent-600`, текст белый |
| Вторичная кнопка | фон белый, граница `border-default`, текст `text-primary` |
| Текстовая кнопка | текст `accent-600`, без фона |
| Опасное действие | текст и граница `danger`, фон белый |
| Выделенная карточка | фон `bg-accent-subtle`, без границы |
| Активный пункт навигации | фон `accent-50`, текст `accent-700` |

### Цвет статусов и приоритетов

Приоритеты заявок — единственное место, где цвет несёт смысл сам по себе:

| Приоритет | Цвет | Индикатор |
|---|---|---|
| `CRITICAL` | `danger` | 🔴 точка + красная левая полоса карточки |
| `HIGH` | `warning` | 🟠 точка |
| `NORMAL` | `text-secondary` | 🟡 точка |
| `LOW` | `text-tertiary` | без точки |

**Цвет никогда не единственный носитель информации** — везде дублируется формой, иконкой или текстом. Дальтонизм встречается у 8% мужчин, а приоритет заявки — это не декоративная деталь.

## 2. Типографика

**Inter** — единственное семейство. Начертания: 400 Regular, 500 Medium, 600 SemiBold, 700 Bold.

| Роль | Размер / интерлиньяж | Начертание |
|---|---|---|
| `display` | 32 / 40 | 700 |
| `h1` | 24 / 32 | 700 |
| `h2` | 20 / 28 | 600 |
| `h3` | 17 / 24 | 600 |
| `body-lg` | 17 / 26 | 400 |
| `body` | 15 / 22 | 400 |
| `body-sm` | 13 / 20 | 400 |
| `label` | 13 / 18 | 500 |
| `caption` | 12 / 16 | 400 |
| `mono-number` | 15 / 22 | 500, табличные цифры |

**`mono-number` обязателен для всех денежных сумм.** Табличные цифры (`font-variant-numeric: tabular-nums`) выравнивают разряды в столбцах — без этого финансовые таблицы выглядят рвано и хуже читаются.

**Форматирование денег:** `8 500 ₸` — неразрывный пробел как разделитель разрядов, символ тенге после числа через неразрывный пробел. Отрицательные суммы — со знаком минус, а не в скобках.

## 3. Отступы, скругления, тени

**Сетка 4 pt:** 2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64.

```
--radius-sm    8px    бейджи, мелкие элементы
--radius-md    12px   кнопки, поля ввода
--radius-lg    16px   карточки
--radius-xl    24px   модальные окна, боттом-шиты
--radius-full  999px  аватары, чипы, круглые кнопки
```

Скругления крупные — это ключевая черта стиля Rentify.

```
--shadow-sm   0 1px 2px rgba(15,23,17,.04)
--shadow-md   0 2px 8px rgba(15,23,17,.06)
--shadow-lg   0 8px 24px rgba(15,23,17,.08)
```

Тени мягкие и почти незаметные. Разделение блоков достигается **фоном и воздухом**, а не границами и тенями. Граница — запасной вариант, когда фон не работает.

## 4. Компоненты

### Карточка

Базовый строительный блок. Белый фон, `radius-lg`, padding 16, `shadow-sm`, без границы. Выделенная — фон `bg-accent-subtle` без тени.

### Кнопка

| Размер | Высота | Padding | Текст |
|---|---|---|---|
| `sm` | 36 | 12 | `body-sm` 500 |
| `md` | 44 | 16 | `body` 500 |
| `lg` | 52 | 20 | `body-lg` 600 |

**Минимальная область нажатия 44×44** даже для визуально мелких кнопок. Работник пользуется приложением в перчатках — это не абстрактное требование доступности.

### Поле ввода

Высота 48, `radius-md`, граница `border-default`, при фокусе — `border-focus` и кольцо `accent-100` толщиной 3px. Ошибка — граница `danger` и текст ошибки под полем.

Метка **над полем**, а не плейсхолдером внутри: плейсхолдер исчезает при вводе, и пользователь забывает, что он заполняет.

### Прогресс заявки

Ключевой компонент — через него жилец видит, что его проблемой занимаются.

```
●───────●───────◐───────○
Осмотр  Закуп   Ремонт  Проверка
 ✓       ✓      сейчас
```

Завершённые — `accent-600` заливка, текущий — `accent-600` контур с пульсацией, будущие — `border-strong`.

### Индикатор кворума

```
Явка по площади      42.3%
████████░░░░░░░░░░░░
                  ↑ 50% нужно
```

Отметка порога обязательна: без неё 42% выглядят как «почти половина», а не как «не хватает».

### Пустые состояния

Каждый список имеет осмысленное пустое состояние: иконка, объясняющий текст, кнопка действия. «Нет данных» не допускается — пустой экран заявок должен звать создать заявку, а не констатировать отсутствие.

## 5. Навигация

### Мобильное — жилец

Нижняя панель, 4 вкладки: **Главная**, **Заявки**, **Финансы**, **Ещё**. Бейдж с числом действий, требующих участия, на «Главной».

### Мобильное — работник

Нижняя панель, 3 вкладки: **Задачи**, **Объявления**, **Профиль**. Ничего лишнего — работник открывает приложение ради одного экрана.

### Мобильное — председатель

Нижняя панель, 4 вкладки: **Главная**, **Заявки**, **Задачи**, **Ещё**.

Бейдж на «Заявках» — число новых, на «Главной» — общее число требующих решения. Плавающая кнопка быстрых действий: голосовая задача, объявление, поручение.

Режим председателя включается автоматически по роли. Если он же собственник в этом доме — переключатель режима в профиле; права не смешиваются.

### Веб — председатель

Боковое меню: Дашборд · Заявки · Задачи · Голосования · Финансы · Отчёты · Жильцы · Персонал · Объявления · Документы · Помощник.

Переключатель дома в шапке — только если домов больше одного.

### Веб — админ-панель

Отдельный раздел с визуально иным оформлением (более плотная сетка, `bg-subtle` фон), чтобы админ не путал контекст платформы с контекстом дома.

## 7. Доступность

Не отдельная задача, а часть определения готовности:

- Контраст текста к фону не ниже **4.5:1** (для крупного — 3:1). Проверено: `text-primary` на белом даёт 16.1:1, белый на `accent-600` — 5.9:1
- Область нажатия не менее 44×44
- Цвет не единственный носитель информации
- Все поля с метками, все изображения с alt
- Полная навигация с клавиатуры в вебе, видимый фокус
- Поддержка системного увеличения шрифта до 200% без потери функциональности

Последний пункт критичен: значительная доля собственников квартир — пожилые люди с увеличенным системным шрифтом. Интерфейс, который при этом ломается, отсекает именно тех, кто по закону имеет право голоса.

## 8. Тексты

**Тон:** простой, уважительный, без канцелярита. Пользователь — не «абонент» и не «пользователь системы».

| Не так | Так |
|---|---|
| «Заявка успешно инициирована» | «Заявка принята» |
| «Отсутствуют данные» | «Заявок пока нет» |
| «Ошибка 422» | «Нельзя начать голосование раньше 16 сентября — закон требует уведомить жильцов за 5 дней» |
| «Некорректный ввод» | «Введите сумму больше нуля» |

**Ошибки объясняют, что делать**, а не констатируют проблему. Особенно в правовых ограничениях: председатель не обязан знать закон наизусть, и сообщение об ошибке — лучшее место, чтобы объяснить требование.

**Языки:** русский (основной) и казахский. Все строки выносятся в i18n с первого дня, даже пока казахская локаль не заполнена. Дозаполнить переводы можно в любой момент; вытащить строки из кода задним числом — дорого и делается плохо.

Форматы: даты `11 сентября 2026`, короткие `11.09.2026`, время 24-часовое, деньги `8 500 ₸`, площадь `62,4 м²` (запятая — десятичный разделитель).
